## 0. 一屏结论

| 实验 | 结论 | 对 unremember 意味着什么 |
|---|---|---|
| **02-A 压缩** | `/compact` 追加 `compact_boundary` + `isCompactSummary` 摘要行；压缩前 182 行原样保留。只抹摘要、原始行不动 → resume 回答 **0 处暗号**；只删原始行、保留摘要 → resume 回答 **3 处暗号**。 | 恢复只加载“当前 surface/摘要”，不会重新加载被压缩掉的原始行；但摘要本身是新的泄漏源，必须扫描并改写摘要。 |
| **02-B 删除边界** | 删 tool_use、删 tool_result、连续 assistant、同 message.id 只删 thinking，5 例 resume 全部 `exit 0 / is_error false`；thinking 文本改动在兼容端点上没有签名错误（Anthropic 官方**未确认**）。 | 不能依赖 Claude Code/API 替我们校验 tool 配对；必须在计划阶段自己做配对和断链修复。 |
| **02-C 运行中检测** | `sessions/<pid>.json` 有 `sessionId`/`pid`；正常退出和强制 kill 都会删掉 `.json` 与 `.key`；没有 session 级锁文件。 | 可靠判定 = 注册文件存在 + pid 存活 + sessionId 匹配；不能只看残留文件。 |
| **02-D fork** | `--fork-session` 前后原 JSONL sha256 完全一致，fork 写到新 `<session-id>.jsonl`；不加 fork 的 resume 会追加原文件；fork 和全新会话都能通过 Read 读到测试 memory。 | verify 必须用 fork；memory 是独立泄漏路径，必须在 fork 前清理，不能只清 transcript。 |
| **02-E dsh 写回** | 单 frame 被拒（header 必须单独一帧）；“header 帧 + 剩余行帧”可 resume；默认 zstd root 下纯 `.jsonl` 被拒；单独 `compression:none` root 可读；`.jsonl` 与 `.zstd` 并存时 backend 直接拒绝。 | dsh 写回必须保留“header 单独 frame + checksum”格式；不能把整段 JSONL 压成一个 frame。 |
| **02-E 锁** | POSIX：`session.lock` 上的 `flock(2)`；Windows：`Local\\dsh-session-lock-<sha256(path.lower())>` 命名内核信号量，**没有文件**。 | Windows 不要找 lock 文件；可用 `session/list` 的 `running` 或 `OpenSemaphore`/`WaitForSingleObject`。 |
| **02-E 分叉** | 没有 CLI fork；复制 session 目录后必须同时改 header `id` 和所有 `delivery-accepted.data.sessionId`，否则报错；改全后 resume 成功，父文件 sha256 不变。 | dsh 的 fork 只能“复制目录 + 全量改 id + 重签/重写”，不能只改文件名。 |
| **02-E compact** | `/compact` 追加 `command/run`、`compaction/start`、`compaction/summary`、`compaction/end`、`command/done`；`shadowedRange{8,82}`、16 个 seq、856 tokens；原始事件仍在。 | compact 是“遮蔽区间 + 摘要”，不是物理删；原始事件仍可被读取，必须按 shadowedSeqs 清。 |
| **02-F Codex** | 安装成功（0.164.0），但 0.164 只接受 `wire_api="responses"`；DeepSeek 只有 Chat Completions，代理捕获到 `/v1/responses` 请求后无法完成。未做删行实验。 | Codex 适配器暂不能按原计划落地；需要 Responses→Chat 代理或 Responses 兼容 provider。 |
| **02-G excise** | 模型确实把暗号写进 memory；`excise cut 10 --yes` 只删 1 个 user 条目，memory 与 history 不变；cut 后 JSONL 仍在 `last-prompt/ai-title/assistant/tool_result/api-request-blob` 里含暗号，resume 直接泄漏。 | excise 的“删回合”实际只删单条目，且完全不清 memory/history/API blob；这正是 unremember 要补的对照组。 |

## 2. 02-A：Claude Code 压缩后的结构

### 2.1 会话与压缩

- 22 条 user 消息；第 2 条含 `青柠绿-7429`；其余 20 条为约 300 字说明。
- 手动 `/compact`；终端显示 `Compacting conversation`，完成后退出。
- JSONL：193 行；`compact_boundary` 在第 182 行：

```json
{"type":"system","subtype":"compact_boundary","parentUuid":null,
 "logicalParentUuid":"<pre-compaction-node>",
 "compactMetadata":{"trigger":"manual","preTokens":7478,"postTokens":2290,
 "cumulativeDroppedTokens":5188,"durationMs":21091,
 "preservedMessages":{"anchorUuid":"<uuid>","uuids":["<3 uuids>"]}}}
```

- 紧随其后是 `type:user`、`isCompactSummary:true`、`isVisibleInTranscriptOnly:true`，`message.content` 为摘要字符串。
- 压缩前 182 行**原样保留**；不是删行，而是追加 boundary + summary，并用 `logicalParentUuid` 接回压缩前节点。
- 摘要文本含暗号；原始 user/thinking 行也仍含暗号。共 10 处命中：原始 user、若干 assistant thinking、`last-prompt`、摘要。

### 2.2 三组恢复

| 组 | 改动 | 暗号命中 | 结果 |
|---|---|---:|---|
| 控制 | 原样 | 3 | 回答直接列出暗号/摘要 |
| A3 | 只把摘要里的暗号替换为 `[REDACTED]`，原始 182 行不动 | **0** | 回答只看到摘要中的 `[REDACTED]`，未加载原始压缩行 |
| A4 | 只保留 boundary + 摘要 + 后续 3 条 preserved 消息，删掉压缩前原始行 | **3** | 摘要泄漏，回答直接给出暗号 |

**结论**：恢复时确实不会重新加载被压缩掉的原始行；但摘要是一条新的、完整的上下文，必须作为 transcript 的一部分扫描/改写。A4 是反例：只删原始行会把摘要留在那里。

### 2.3 备注

- 变体读取使用 `--fork-session`，避免把问题追加进原会话；`pristine.jsonl` 保留。
- 模型在只有 `--tools ''` 时一度输出 DSML 工具调用文本；后续提示明确“不要用工具、只按上下文回答”，最终三组答案可判定。
- 摘要 `parentUuid` 指向 boundary，`logicalParentUuid` 指向压缩前节点；原始行仍在时，`logicalParentUuid` 仍可走回旧链。

## 4. 02-C：Claude Code 运行中检测

### 4.1 注册文件

运行中，`<config>/sessions/` 下：

- `<pid>.json`（604 字节左右）
- `<pid>.<sha256>.key`（120 字节）

`.json` 字段（脱敏）：

```json
{"pid":<pid>,"sessionId":"<uuid>","cwd":"<cwd>","startedAt":<ms>,
 "procStart":<...>,"version":"2.1.309","peerProtocol":...,
 "peerFeatures":[...],"kind":"...","entrypoint":"...","pidDomain":"...",
 "messagingSocketPath":"...","name":"...","nameSource":"...","nameSince":...,
 "status":"...","updatedAt":<ms>,"statusUpdatedAt":<ms>}
```

可以从 `.json` 直接拿到 `sessionId` 和 `pid`，且两者与实际 pty/进程一致。

### 4.2 退出清理

- 正常 `/exit`：`exited=true`，`sessions/` 变为空（`.json` 和 `.key` 都删）。
- 强制 kill（`p.kill()`）：同样变空。
- 因此**残留文件不能作为运行中证据**；文件存在 + pid 活着 + sessionId 匹配才是。

### 4.3 锁

- 没有 session 级锁文件；扫描测试 home 的 `lock` 只命中插件市场的 `bun.lock`。
- 可靠判定：
  - Windows：`Get-Process -Id <pid>`；读取 `sessions/<pid>.json` 的 `sessionId`；两者都匹配。
  - macOS/Linux：`ps -p <pid> -o pid=,comm=`；`jq -r .sessionId ~/.claude/sessions/<pid>.json`；两者都匹配。
- 更保守：文件存在且 pid 存活即可拒绝执行；sessionId 用于防 pid 复用。

## 6. 02-E：dsh 写回、锁、分叉、compact

### 6.1 默认 zstd 格式

测试会话 5 个 turn，默认 `session.v4.jsonl.zstd`；解压后 65 个事件：

`session` 1、`agent/inbox/spliced` 10、`turn/start` 5、`user/message` 7、`assistant/message` 5、`turn/end` 5、`request/header` 5、`session/end-seed` 4 等。暗号在 `agent/inbox/spliced`、`user/message`、`assistant/message` 三类事件中。

### 6.2 三种写回

| 写法 | 结果 | 错误/说明 |
|---|---|---|
| (a) 所有行压成单个 `zstdCompressSync` frame + checksum | **失败** | `corrupt Zstandard session log: first frame is not exactly one header line` |
| (a2) header 单独一帧 + 剩余行一帧，均 checksum | **成功** | resume 后回答 `unknown`（暗号已抹）；这是可用的写回格式 |
| (b) 写 `session.v4.jsonl`，删 `.zstd`，默认 zstd backend | **失败** | `uses .jsonl, but this backend is configured for compression "zstd"` |
| (b2) 单独 root + `compression:none`，root 中只有 `.jsonl` | **成功** | resume 后回答 `unknown`；同一 root 只要有一个 `.zstd` 会话就会整体拒绝 |
| (c) `.jsonl` 和 `.zstd` 同时存在 | **失败** | backend 报 `.jsonl` 与 zstd 配置冲突，**不是“选一个读”** |

**产品结论**：dsh 写回不能把整个 JSONL 压成一个 frame；必须保留“header 单独 frame + checksum”，并保持 root 编码一致。

### 6.3 writer lock

源码 `@deepseek-ai/dsh-session-persistence-jsonl/lib/index.js:561`：

- POSIX：`session.lock` 文件上的非阻塞 `flock(2)`；文件在 release 后**不删除**。
- Windows：`Local\\dsh-session-lock-<sha256(resolve(path).toLowerCase())>` 命名内核信号量；**不落文件**。
- 外部只读判断：
  - 最稳：dsh web `session/list` 的 `running` 字段（本次用 `/api/session/list` 验证了返回结构）。
  - Windows：按上面公式算名字，用 `OpenSemaphore` + `WaitForSingleObject(handle, 0)`；`WAIT_TIMEOUT` = 有 writer。
  - POSIX：`lsof <session.lock>`/`fuser` 看是否有进程持有；不要 `flock` 测试，因为那会抢锁。

### 6.4 分叉

- dsh CLI 没有 fork 子命令；`--session-id` 只是 resume/adopt。
- “复制整个会话目录、改 id、再 resume”可行，但必须改**所有**地方：
  1. header `session.id` / 目录名；
  2. `session-log-deepseek/delivery-accepted.data.sessionId`（否则报 `current-generation delivery marker names the wrong Session`）；
  3. 其他事件里的 `session-...` 字符串。
- 第一次只改 header 失败；全量替换后 resume 成功，父文件 sha256 不变（`B105D0...` 前后一致），新文件有新 sha。

### 6.5 `/compact`

通过测试 dsh web 的 `commands/execute`（`agentId=<session>`、`line="/compact"`、`submittedAttachments=[]`）触发，返回：

```text
Compacted 16 history items (~856 tokens). sourceEventSeq=93
```

日志新增：

- `command/run` seq 90：`{commandId,name:"compact",args:"",source:{kind:"user"}}`
- `compaction/start` seq 91：`{compactionId,sourceCommandId,turn:null}`
- `compaction/summary` seq 93：`summary`, `rawOutput`, `llmStreamCall`, `shadowedRange:{start:8,end:82}`, `shadowedSeqs:[...16]`, `shadowedTokenCount:856`, `provider`, `model`, `usage`
- `compaction/end` seq 95
- `command/done` seq 96：`{kind:"success",text:"Compacted 16 history items (~856 tokens).",sourceEventSeq:93}`

原始事件 0–90 仍全部在日志里；compact 只是追加 summary 和 shadow 区间，不物理删。
