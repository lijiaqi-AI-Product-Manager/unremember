## 02-A　Claude Code 压缩后的结构
1. 建一个测试会话：第 2 条消息埋暗号，然后再聊 20 轮以上无关内容（可以让模型每轮输出一段 300 字的说明，把长度撑起来），再手动执行 `/compact`。
2. 记录：压缩后 JSONL 里新增了哪些条目（type、subtype、字段，脱敏样例）；摘要文本里有没有暗号；`parentUuid` / `logicalParentUuid` 怎么接；压缩前的原始行还在不在。
3. 实验：只抹掉**摘要**里的暗号（压缩前的原始行不动）→ resume → 问任务书 01 里的 5 个问题。**被压缩掉的原始行在恢复时还会不会被加载？**（预期：不会。请确认。）
4. 再做一组：只删压缩前的原始行、保留摘要 → 看会不会泄漏（预期：会，因为摘要里有）。

## 02-B　Claude Code 删除的边界情况（每种都要 resume，并记录有没有报错和报错原文）
1. 删掉一个 `tool_use`，但保留对应的 `tool_result`。
2. 删掉一个 `tool_result`，但保留对应的 `tool_use`。
3. 删完之后出现两条连续的 user 条目，或两条连续的 assistant 条目。
4. 改掉一个 thinking 块里的文字（不删）——会不会触发签名错误？注意：这个只能在 Anthropic 官方端点上测出来，如果用的是兼容端点，写"未确认"。
5. 删掉同一个 `message.id` 下的部分条目（只删 thinking，留下 text）。

## 02-C　Claude Code 运行中检测
1. 会话运行时，`~/.claude/sessions/` 下的文件叫什么名字、有哪些字段（脱敏）、能不能从里面拿到 sessionId 和 pid；正常退出、强制结束（Ctrl+C 两次 / kill）之后，这个文件会不会被删掉。
2. 有没有锁文件，或者其他能证明"这个 sessionId 正在被使用"的东西。
3. 给出一个**可靠的判定方法**：pid 是否还活着 + sessionId 是否匹配。附 Windows 和 macOS / Linux 两种检查 pid 的命令。

## 02-D　Claude Code 分叉不污染原会话
1. `claude -p --resume <id> --fork-session "问题"`：原会话 JSONL 的 sha256 前后是否一致；新会话文件出现在哪里。
2. 不加 `--fork-session` 时，原文件是否会被追加写入（对照组）。
3. 分叉出来的会话能不能读到 auto-memory？（verify 需要确认"从 memory 泄漏"这条路能被测出来。）

## 02-E　dsh 写回和运行中检测
1. 默认的 `session.v4.jsonl.zstd`：用 Node 22 的 `zlib.zstdDecompressSync` 解压，改好后再写回。分别测三种写法能不能 resume、会不会报 corruption：
   - (a) `zstdCompressSync` 单个 frame、开启 checksum；
   - (b) 写成不压缩的 `session.v4.jsonl`，并删掉 `.zstd` 文件；
   - (c) `.jsonl` 和 `.zstd` 同时存在时，dsh 读的是哪一个。
2. dsh 运行中检测：它的 writer lock 是什么形式（锁文件路径 / 命名信号量的名字 / 端口）？外部程序怎么只读地判断"这个会话正在运行"？
3. dsh 的分叉：有没有命令行方式，可以从一个会话分叉出子会话并问一个问题，而父会话的文件不变（用 sha256 证明）？如果没有，"复制整个会话目录、改 id、再 resume"可不可行？
4. dsh 的 `/compact`：触发一次，记录压缩事件的结构，以及原始事件还在不在。

## 02-F　Codex 实测（能装上就做，装不上写原因）
1. 安装 `@openai/codex@0.164.0`。在 `CODEX_HOME` 测试目录的 `config.toml` 里配一个 OpenAI 兼容的 provider（比如 DeepSeek），不要用真实的 OpenAI 账号。
2. 照任务书 01 的流程做：埋暗号 → 删 `response_item` 行 → resume → 5 个问题 → 对照组。
3. 触发压缩后，验证 `compacted.replacement_history` 会不会把删掉的内容"带回来"，以及同时改掉它之后能不能恢复成功。

## 02-G　excise 基线
1. 装好 Go，`git clone https://github.com/SuperMarioYL/excise`，`go build ./cmd/excise`。
2. 用 02-A 的方式建一个测试会话，并且**让模型把暗号写进 memory**（开着工具，明确说"请把暗号记到你的记忆里"）。
3. 用 excise 删掉含暗号的那个回合（`cut`，要带 `--yes`）→ resume → 5 个问题。
4. 记录：excise 改了哪些文件、漏掉了哪些副本（`history.jsonl`、memory、file-history、api-request-blob），以及泄漏结果。**这一组数据会成为 README 里的对照组，请严格按事实记录。**
