# unremember 规格 v0.1

> 给 agent 一碗孟婆汤：从本地 agent 会话里定向删掉一段内容（连同它的复述和会话外的副本），并用追问证明 agent 真的忘了。
>
> 依据：[调研结果-01](调研/调研结果-01.md)、[调研结果-02](调研/调研结果-02-国内平台.md)、[调研结果-03](调研/调研结果-03-补充实验.md)。本文写"实测"的地方，出自 01 的第 2 节；写"03-x"的地方，出自调研结果-03 的对应实验。
>
> **注意**：Claude Code 的全部实验用的都是 DeepSeek 的 Anthropic 兼容端点。所以凡是"API 会不会报错"这类结论，到了 Anthropic 官方端点上都还**未确认**。我们的设计不依赖这些结论，宁可自己把规则守得更严。

## 1. 范围

**MVP 支持**：Claude Code（≥2.1.30x）、dsh（0.2.x，session v4）。
**MVP 不做**：Codex（03-F：0.164 只接受 Responses API，没有能用的测试 provider，实验没能做成，放进路线图）、国内平台（放进路线图）、云端会话、正在运行的会话。

**我们承诺的**：恢复会话之后，模型的上下文里不再有目标内容；本机上已知的副本也都清掉；用 verify 给出泄漏率。
**我们不承诺的**（README 必须写明）：服务器端的留存和日志、遥测、已经写进项目代码或提交进 git 的内容、其他机器、云端会话、模型权重。

## 2. 名词

| 名词 | 含义 |
|---|---|
| **目标（Target）** | 用户要忘掉的东西。三种写法：一段字面文本（`--text`）、一条消息的 id（`--message`）、一句自然语言描述（`--about "我上周贴的那个 API key"`，必须配合 `--semantic` 使用） |
| **命中（Hit）** | 在某个存储里找到的一处目标内容：位置、命中方式（精确 / 语义）、置信度、所在的片段 |
| **存储（Store）** | 一个可能存着内容的地方：会话 JSONL、`history.jsonl`、memory 文件、file-history 快照…… |
| **操作（Op）** | 对一个存储的一次改动：`delete-entry`、`redact-span`、`blank-field`、`delete-file`、`delete-line`、`relink` |
| **计划（Plan）** | 一次遗忘的全部操作清单，带 id；dry-run 的产物，存成文件，可以复查 |
| **适配器（Adapter）** | 一个平台的读、定位、出计划、执行逻辑 |

## 3. 数据模型

```ts
type Platform = 'claude-code' | 'dsh'

interface SessionRef { platform: Platform; sessionId: string; file: string; projectDir?: string }

interface Target {
  text?: string[]            // 字面文本，可以是多个变体（例：完整暗号 + 只有数字的部分）
  messageIds?: string[]      // Claude 的 uuid / dsh 的 seq
  about?: string             // 自然语言描述，只用于语义定位
}

interface Hit {
  store: StoreRef            // { kind: StoreKind; path: string }
  locator: Locator           // 行号 + JSON 指针（例：/message/content/1/text）+ 片段的起止位置
  how: 'exact' | 'semantic' | 'dependency'
  confidence: number         // 精确命中 = 1；语义命中由模型给出
  excerpt: string            // 只在终端里显示，不写进计划文件
  reason?: string            // 语义 / 依赖命中的理由
}

type StoreKind =
  | 'cc-transcript' | 'cc-subagent' | 'cc-history' | 'cc-memory' | 'cc-memory-index'
  | 'cc-file-history' | 'cc-paste-cache'
  | 'dsh-session' | 'dsh-session-old-gen' | 'dsh-storage' | 'dsh-attachment'

interface Plan {
  id: string                 // 时间戳 + 短哈希
  createdAt: number
  session: SessionRef
  target: Target             // 写入时只存 sha256，不存原文（防止计划文件本身变成副本）
  fingerprint: FormatFingerprint
  ops: Op[]
  files: Array<{ path: string; sha256Before: string }>   // apply 前会校验这些文件没被改过
  warnings: string[]
}
```

**原则**：plan 文件、备份清单和日志里**都不存目标原文**。备份本身当然含原文，所以存在 `~/.unremember/backups/<plan-id>/` 里，README 要提醒用户：确认无误后执行 `unremember purge-backups` 把备份也删掉。

## 4. 流水线

### 4.1 定位
1. **精确匹配**：对每个存储的全部文本字段做子串匹配。匹配前统一做 NFKC 规范化、去掉零宽字符；JSON 字符串先反转义再匹配（调研里提到过 JSON 转义导致漏匹配的坑）。
2. **语义匹配**（`--semantic`，默认关闭，因为要把片段发给模型）：只看"第一次精确命中之后"的消息，按约 2K token 一窗切开。先做一遍预过滤：把目标拆成若干关键成分（例："青柠绿""7429""暗号"），窗口里至少出现一个成分，或者明显指代了它，才送给模型，以控制成本。模型返回 JSON：`[{locator, span, confidence, reason}]`。置信度 ≥ 0.7 的列入计划，0.4–0.7 的列为"建议复查"，需要用户确认。
3. **memory 文件**：先做精确匹配；再判断这个文件是不是"专门为目标而写的"（文件名或标题里含目标成分，或者超过一半的内容在讲它）。是的话整个文件删掉，并删掉 `MEMORY.md` 里的索引行；否则只删掉命中的句子。

### 4.2 扩展（依赖闭包）
- **Claude Code**
  - 删一条用户提示 ⇒ 这一回合里模型的全部条目也删（同一个 `message.id` 下的 thinking、text、tool_use 一起删），这些 tool_use 对应的 `tool_result`（同一个 `tool_use_id`）也删。
  - **tool_use 和 tool_result 必须成对删或者成对留**，否则 API 会直接报错。这是硬约束。
  - 只在后续回合里被复述的（例：thinking 里提了一句）：thinking 块整块删掉（改了带签名的 thinking 会出问题，所以不改，只删）；text 块里的命中只删那几句话（redact-span），不删整条条目。
  - `last-prompt`：如果它的 `leafUuid` 指向被删的条目，就改成最近的保留祖先；如果 `lastPrompt` 文本里含目标，也一并抹掉。
  - `ai-title` 里含目标 ⇒ 改成"（已编辑的会话）"。
  - `api-request-blob.message` 和 `api-request.params` 里含目标 ⇒ 删掉整行（实测证明它们不参与恢复）。
  - `attachment` 指向被删的 memory 文件 ⇒ 删掉这条 attachment（实测发现这些指针残留会让模型去找那份记忆文件）。
  - `file-history-snapshot` / `delta` 指向的备份文件里含目标 ⇒ 对备份文件做 redact。
  - `history.jsonl`：删掉 `display` 含目标、并且 `sessionId`（或项目路径）匹配的那几行。
  - **压缩摘要**（03-A）：`compact_boundary` 后面那条 `isCompactSummary: true` 的 user 条目，是恢复时真正被加载的内容，**是最重要的泄漏源**。实测只改写摘要，泄漏为 0；只删原始行、保留摘要，泄漏 3 处。处理办法：摘要里的命中按句改写，不删条目。压缩前的原始行恢复时不会加载，但它们仍然是磁盘上的副本，所以照常删除并重接；`logicalParentUuid` 也要走同一套重接逻辑。`compactMetadata.preservedMessages.uuids` 里如果有被删的 uuid，就从列表中去掉。
  - **配对必须自己保证**（03-B）：Claude Code 不会因为 tool 配对断裂、连续同角色、thinking 缺失而拒绝恢复，它会悄悄地规整掉。所以没有任何报错能兜底，配对检查必须由我们在出计划时完成。
- **dsh**
  - **不删行**（实测：删行再重编号会导致 inbox 重放）。只抹空这些字段：`user/message.data.content[*].text`、`assistant/message.data.message.content[*].text` 和 thinking、`assistant/message.data.stream = []`、`...source.replayState = {}`、`agent/inbox/spliced.data.inserted[*].content[*].text`。
  - 后续消息里的复述：只删命中的那几句话。
  - `session/title*` 里含目标 ⇒ 抹掉。
  - 历史 generation 文件（`session.v1..v3`）里含目标 ⇒ 做同样的抹除。
  - **压缩**（03-E）：`/compact` 会追加 `compaction/summary` 事件（含 `summary`、`rawOutput`、`shadowedRange`、`shadowedSeqs`），原始事件不删、只是被遮蔽。`summary` 和 `rawOutput` 里的命中按句改写；被遮蔽的原始事件照常抹空。

### 4.3 Claude Code 断链修复（relink）
```
deleted = 被删的 uuid 集合
对每一条保留下来的条目 e：
  对 field ∈ {parentUuid, logicalParentUuid}：
    p = e[field]
    当 p ∈ deleted 时：p = parentOf(p)     // 沿着被删的节点一路往上找
    e[field] = p                            // 可能变成 null（被删的是根）
```
修复后的自检：没有悬空的 parent；从 leaf 往上能走到根；条目总数 = 原来的数目 − 删掉的数目；tool_use / tool_result 是配对的。**任何一项不过，就拒绝执行。**

### 4.4 出计划（dry-run，默认行为）
终端里显示：每个存储有几处命中、每项操作（`- 删除` / `~ 改写` / `→ 重接`），以及摘录（目标文本遮掉一半显示，例：`青柠██-74██`）。`--json` 输出机器可读的格式。计划写入 `~/.unremember/plans/<id>.json`。

### 4.5 执行
1. **运行中检测**：会话正在运行就拒绝执行。
   - Claude Code（03-C）：在 `<config>/sessions/` 下找 `sessionId` 匹配的 `<pid>.json`，并且这个 pid 还活着，就判定为运行中。正常退出和强制结束都会把这个文件删掉，所以没有文件就说明不在运行；有文件但 pid 已死，说明是残留，不算运行中。
   - dsh（03-E）：POSIX 上看 `session.lock` 有没有被进程持有（用 `lsof`，不能自己去 `flock`，那样会抢锁）；Windows 上是一个命名信号量 `Local\dsh-session-lock-<sha256(resolve(path).toLowerCase())>`，用 `OpenSemaphore` + `WaitForSingleObject(h, 0)` 判断，返回 `WAIT_TIMEOUT` 说明有 writer。**检测失败（例如没有权限）一律按"正在运行"处理。**
2. 校验 `sha256Before`：文件在出计划之后被改过的话，拒绝执行，要求重新出计划。
3. 备份到 `~/.unremember/backups/<plan-id>/`，写一份 `manifest.json`（原路径 + sha256）。
4. 原子写入：先写临时文件，再 rename。
   - dsh 的 `.zstd` 文件（03-E）必须写成**两个 frame：header 一行单独一个 frame，其余行一个 frame，两个都带 checksum**。整个文件压成一个 frame 会被拒绝；也不能改成纯 `.jsonl`，因为同一个 root 里的编码必须一致，`.jsonl` 和 `.zstd` 并存会被拒绝。
5. 写一条操作日志到 `~/.unremember/journal.jsonl`，只写 plan id、文件、操作数和哈希。

### 4.6 验证（verify）
- **一定在分叉上做**：原会话不能被追问的内容污染。
  - Claude Code（03-D）：用 `claude -p --resume <id> --fork-session`，原文件的 sha256 不会变；不加 `--fork-session` 的话，问答会被追加进原文件。分叉会话能读到 memory，所以"从 memory 泄漏"这条路径也能被测出来。
  - dsh（03-E）：没有 fork 命令。做法是把会话目录复制到一个临时 `DSH_HOME` 下，换一个新的会话 id，把文件里**所有**出现旧 id 的地方都替换掉（header 的 `id`、`delivery-accepted.data.sessionId` 等，漏一处就会报错），再按两个 frame 的格式写回，然后在临时 home 里恢复会话。
- verify 结束后要删掉分叉出来的会话文件和临时 home（分叉里含有追问的内容）。
- **追问题库**（20 题，分 5 类，每类 4 题）：直接问、间接或给提示、让它列出全部对话、让它原样输出上下文、让它去查文件和记忆（"看看你的记忆文件里有没有……"）。
- **判定**：
  1. 回答里出现目标的任一字面变体或关键成分 ⇒ 泄漏；
  2. 否则交给裁判模型判断"这个回答是否透露了目标的信息"（`--semantic` 时才启用）；
  3. 模型去读的文件路径或文件名里含目标成分 ⇒ 记为"指针残留"（不算泄漏，但要报告）。
- **输出**：泄漏率 = 泄漏题数 / 20；分类明细；残留的指针。退出码：0 = 没有泄漏，1 = 有泄漏。

### 4.7 回滚
`rollback <plan-id>`：按 manifest 把文件还原，并校验哈希一致。`purge-backups [<plan-id>]`：删掉备份（会二次确认）。

## 5. 格式指纹（防止官方改格式后把文件写坏）
- **Claude Code**：取条目的 `version` 字段，再统计条目类型。出现没见过的类型时，**仍然对它做精确扫描**，但只要它含命中，就拒绝执行，并提示"格式可能变了"。
- **dsh**：检查 header 的 `version === 4`；其他版本拒绝执行。
- 文件里没有我们认识的结构 ⇒ 拒绝执行。

## 6. 命令行
```
unremember sessions [--platform cc|dsh] [--cwd <dir>]         列出会话（id、开始时间、首条提示的前 20 个字）
unremember plan <session> (--text <s>... | --message <id>... | --about <s>) [--semantic] [--json]
unremember apply <plan-id> [--yes]
unremember verify <session> --canary <s>... [--probes 20] [--semantic]
unremember resume <session>                                     执行待办的遗忘请求，然后恢复会话
unremember rollback <plan-id> | purge-backups [<plan-id>]
```
`<session>` 可以是会话 id、id 前缀，也可以是 `last`（当前目录下最近的一个会话）。

## 7. skill 入口
用户在对话里说"把刚才那个暗号忘掉"，skill 会：
1. 和用户确认要忘的具体是什么；
2. 写一条待办请求到 `~/.unremember/pending/<sessionId>.json`（只存目标的哈希和描述 + 一份经确认的字面文本，放在备份目录同级、权限 600）；
3. 告诉用户：退出会话，然后执行 `unremember resume <id>`。

skill 自己**不去改会话文件**（会话还在运行，改了也不生效）。

## 8. 隐私
- 默认完全离线，只做精确匹配。
- 加了 `--semantic`，才会把命中附近的窗口发给配置的模型接口；终端里要先显示要发送的字节数，并请求确认（`--yes` 可以跳过）。
- 计划、日志、待办文件里只存哈希。

## 9. 验收（对应实现计划的第 1–5 条）
用合成会话的夹具跑单元测试；端到端测试用真实的 CLI 加测试 home 目录（`CLAUDE_CONFIG_DIR`、`DSH_HOME` 指向临时目录），绝不碰用户真实的 home 目录。
